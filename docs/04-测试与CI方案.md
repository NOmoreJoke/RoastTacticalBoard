# 《吐槽战术板》测试方案与 CI 流水线

> 版本：v0.9　|　日期：2026-09-14

---

## 1. 测试策略总览

| 层级 | 工具 | 范围 | 执行时机 |
|---|---|---|---|
| L1 单元测试 | Jest 29 | `utils/` 全部纯逻辑（模型/标签/过滤/编码/存储/榜单） | 本地 + CI 每次 push |
| L2 静态检查 | ESLint | 全部 JS（页面 + utils + tests） | 本地 + CI 每次 push |
| L3 编译校验 | 微信开发者工具 CLI / miniprogram-ci | 小程序能否编译通过、包体积、配置合法 | 本地发布前；CI 可选（需密钥） |
| L4 真机回归 | 人工清单（见 §4） | 拖拽手感、Canvas 渲染、授权流、分享链路 | 每次提审前 |

**分层原则**：MVP 无后端，所以测试重心在 L1/L2 —— 把"画不出来的 bug"（数据坏、编码错、过滤漏）全部拦截在单元层；L4 只验证"手感与渲染"。

## 2. L1 单元测试清单（本次已实现，`tests/` 目录）

| 测试文件 | 覆盖点 | 关键用例 |
|---|---|---|
| `board.test.js` | 数据模型与业务规则 | 创建默认板（篮球5人/足球7人*2队）；validateBoard 拦截：坏 sport、坐标越界（越界坐标被裁剪）、超长标题、气泡>10、球员>22、箭头 kind 非法；roastValue 求和；aggregateRoastValue 按 target 聚合出榜单；duplicateBoard 深拷贝与 id 重生成 |
| `tags.test.js` | 标签库 | 预置库完整性（篮球/足球/通用三分类、无重复 id/name、每个含 emoji+category）；自定义标签：≤8 字、重名拒绝、敏感词拒绝；`tagsForSport` 返回 sport+通用合集 |
| `safety.test.js` | 本地攻击性词过滤 | 直接命中、全角/符号变体（"傻*逼"）、正常词误伤白名单（"射门""犯规"不误杀）、空串 |
| `share.test.js` | 吐槽码 | encode→decode 往返一致；checksum 坏数据拦截（改 1 字符必失败）；前缀错误/非 base64/JSON 破损/版本不识别 → 各自的可读错误；老版本兼容分支 |
| `avatar.test.js` | 形象方案 | 12 色 × 24 表情网格存在且不重复；`randomStrangerAvatar` 随机性与值域；号码 0-99 裁剪 |
| `storage.test.js` | 存储层 | 注入内存 backend 的 CRUD；saveBoard 触发 validate；超 200KB 拒绝；duplicate/remove 幂等 |
| `format.test.js` | 小工具 | 相对时间（刚刚/x分钟前/昨天）、千分位 |
| `courts.test.js` | 球场配置 | 篮球/足球配置存在、aspect 合理、paint 为函数（渲染本身归 L4） |

**覆盖率门槛（CI 卡点）**：`utils/` 语句覆盖 ≥ 80%，`board.js`/`share.js`/`safety.js` ≥ 90%。

## 3. L2 ESLint 规则要点

- `eslint:recommended` 基线 + 全局 `wx`/`App`/`Page`/`Component`/`getApp` 声明。
- 禁 `eval`、禁未使用变量、`eqeqeq`；utils 目录禁引用 `wx` 全局（`no-restricted-globals`，架构守护）。

## 4. L4 真机回归清单（提审前手动执行，勾选式）

**编辑器**
- [ ] 篮球/足球底图渲染正确，DPR 下线条清晰
- [ ] 球员拖拽跟手、边界不出画布、松手后吸附的箭头跟随
- [ ] 三种箭头绘制/撤销/擦除；吸附阈值体验正常
- [ ] 气泡创建（模板/标签/@对象）、拖拽、上限 10 个
- [ ] 路人一键生成的名字/形象每次不同；同名追加 #号码
- [ ] 敏感词在 标签/吐槽/标题/球员名 四个入口均被拦截

**导出与分享**
- [ ] 750×1000 导出图内容完整无溢出，气泡层级正确
- [ ] 保存相册：首次授权弹窗 / 拒绝后引导 openSetting
- [ ] 图片分享菜单成功唤起（低版本基础库隐藏该入口）
- [ ] 卡片转发：好友点开标题与封面正确
- [ ] 吐槽码复制→另一台设备导入成功；坏码提示可读

**其余页面**
- [ ] 板列表增删改复制；删除有二次确认
- [ ] 点赞 +1 飘字、榜单排序正确、刷新后保持
- [ ] 形象/名单/自定义标签 CRUD 生效且反映到编辑器

## 5. CI 流水线（GitHub Actions：`.github/workflows/ci.yml`）

```
push / PR → main
 ├── job lint：npm ci → eslint .
 ├── job test：npm ci → jest --coverage → 上传覆盖率 artifact → 覆盖率门槛卡点
 └── job package-check（始终执行，无需密钥）：
       校验 miniprogram 目录结构 / app.json 页面文件齐全 / project.config.json 合法（node 脚本）
```

- Node 20；缓存 npm。
- 可选 job `miniprogram-ci-preview`（`workflow_dispatch` 手动触发）：读取 Secrets `MP_APP_ID`、`MP_PRIVATE_KEY`（上传密钥）调用 `scripts/preview.js` 生成预览二维码 —— 密钥不入库，见 README 配置说明。
- 分支策略：`main` 保护 + 功能分支 PR；commit message 采用 Conventional Commits（`feat:`/`fix:`/`docs:`/`test:`/`chore:`）。

## 6. 缺陷管理约定（轻量）

- Issue 模板字段：机型/基础库版本/复现步骤/截图/严重级（S1 阻断- S4 建议）。
- S1/S2 修复不进版本文档不发版；每次提审附带当轮 L4 清单勾选结果。
