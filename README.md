# 🔥 吐槽战术板 RoastTacticalBoard

> 热血动漫风的团体运动吐槽小程序：赛后 1 分钟，把队友（或野球场神秘路人）的迷惑选择和战术跑位画成一张可分享的吐槽图。
> 当前版本：**V0.1 MVP**（纯本地单机版，无后端、不收集任何信息）

📖 产品文档：[需求 PRD](docs/01-需求文档-PRD.md) · [MVP 设计](docs/02-MVP设计文档.md) · [迭代计划](docs/03-迭代计划.md) · [测试与 CI](docs/04-测试与CI方案.md)

## ✨ MVP 功能

- 🏀⚽ **篮球/足球战术板编辑器**：球场画布、球员拖拽、传球/跑位/出手三种箭头（带吸附与撤销）、漫画吐槽气泡
- 🎭 **队友 + 虚拟路人**：熟人从名单上场；野球局的路人一键生成随机虚拟角色（帽衫神秘人、扫地僧……）
- 🏷 **恶搞称号标签**：随缘射手、吐饼大师、射正王、嘴强王者……支持自定义（内置攻击性词本地过滤）
- 🎨 **一键生成吐槽图**：750×1000 海报，保存相册/图片分享/小程序卡片转发
- 📋 **吐槽码**：无后端也能把整块板无损发给好友导入
- 🔥 **本机吐槽值与排行榜**：点赞聚合，Top20 热血领奖台
- 🙌 **我的形象**：12 色 × 24 表情 × 号码自定义形象 + 球员名单 + 我的称号

## 🚀 本地运行

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
2. 克隆本仓库后，开发者工具 → 导入项目 → 选择**仓库根目录**（`project.config.json` 所在处）
3. AppID 一栏：没有注册小程序时选「测试号/游客模式」；已注册则填入你的 AppID
4. 编译即可体验全部功能（MVP 无后端，无需任何域名配置）

## 🧪 开发与测试

```bash
npm install        # 安装依赖（jest / eslint / miniprogram-ci）
npm test           # 单元测试（67 用例，覆盖率卡点 ≥80%）
npm run lint       # ESLint 静态检查
npm run check:package  # 小程序包结构校验
```

架构约定：`miniprogram/utils/` 为纯逻辑层，禁止引用 `wx` 全局（ESLint 强制），全部可被 Jest 直接测试；页面层只做交互编排。

## 🚢 CI

GitHub Actions（`.github/workflows/ci.yml`）在 push/PR 时执行：ESLint → Jest（覆盖率卡点 + artifact）→ 包结构校验。
另有一个手动触发的 `mp-preview` job（见下）。

## 📅 明日部署：备案 + 上线操作指南（2026-09-15）

> 目标：注册小程序主体 → 完成备案 → 上传审核 MVP。全程约 1-3 个工作日（审核时间为等待，操作本身约 1 小时）。

### 第 1 步：注册小程序（约 20 分钟）

1. 打开 [微信公众平台](https://mp.weixin.qq.com/) → 立即注册 → 选「小程序」
2. 主体类型选择建议：**个人主体**（免企业资质，最快；后续社区化若需「社交-社区」类目再升级企业主体）
3. 准备材料：身份证 + 手机号 + 一个未绑定过公众平台/小程序的邮箱
4. 填写小程序信息：
   - 名称：建议 **「吐槽战术板」**（与代码内名称一致，过审更顺；被占用则备选「友尽战术板」）
   - 简介：「画下球场上的欢乐名场面，生成吐槽战术板与好友分享」
   - 类目（重要）：选 **工具 > 效率** 或 **工具 > 信息查询**（个人主体可选范围内；不要选社交类，规避 UGC 审核）

### 第 2 步：小程序备案（约 15 分钟操作 + 等待审核）

1. 平台首页 → 「备案」小程序备案 → 新增备案
2. 填写主体信息（身份证）、负责人信息，人脸核验
3. 服务内容：选「其他-工具类」，声明**不提供用户发布内容的公开发布服务**（MVP 无社区，属实）
4. 提交后微信侧初审 1-2 天，随后转管局审核；**备案期间小程序不能发布上线，但可以先上传开发版本**

### 第 3 步：关联 AppID 并上传代码（约 10 分钟）

1. 平台「开发管理 → 开发设置」拿到 **AppID**
2. 「开发设置 → 小程序代码上传密钥」→ 生成并下载私钥文件（用于 CI，见下节；文件放仓库外）
3. 本地：`project.config.json` 中把 `appid` 从 `touristappid` 改为你的 AppID
4. 开发者工具 → 导入项目 → 预览真机跑一遍（编辑器画板 → 出图 → 保存相册 → 吐槽码导入）
5. 工具右上角「上传」→ 填版本号 `0.1.0` 与备注 → 上传成功

### 第 4 步：提交审核（备案通过后，约 10 分钟）

1. 平台「版本管理 → 开发版本」→ 提交审核
2. 声明页注意：
   - 用户信息收集：**不收集**（MVP 纯本地）
   - 隐私保护指引：选「不收集任何用户信息」
3. 审核通常 1-2 天；通过后「发布」即上线

### 常见拒审与规避

| 问题 | 规避 |
|---|---|
| 名称与功能不符/重名 | 名称含「战术板」，简介呼应功能 |
| 类目不符 | 只选工具类目，隐藏任何社区话术 |
| 诱导分享 | 代码内分享文案不含「分享后才能…」等强制话术（已规避） |
| 内容安全 | 本地敏感词过滤已内置；上线声明为纯工具 |

## 🔐 CI 与真机预览（可选）

仓库 Secrets（环境 `mp-deploy`）配置两个值后，可在 Actions 手动触发 `mp-preview` 生成预览二维码：

- `MP_APP_ID`：小程序 AppID
- `MP_PRIVATE_KEY`：代码上传私钥**文件内容**（CI 内写入临时文件使用，不入库）

本地同样可用：`MP_APP_ID=xxx MP_PRIVATE_KEY_PATH=/path/private.key npm run preview:mp`

> ⚠️ 上传私钥等同发布权限，严禁提交到任何仓库或发到群里。
